## 2. Project Overview

This project focuses on developing a REST API using Node.js, Express.js and SQLite. It converts basic book management routes into a structured REST API with support for HTTP methods, query parameters, search, sorting, pagination, price filtering and input validation.

The API allows users to perform CRUD operations (Create, Read, Update and Delete) on book records stored in an SQLite database.

Postman is used to test the API endpoints and verify successful responses, validation errors and appropriate HTTP status codes.

## 3. Objectives

- Develop RESTful API endpoints using Express.js.
- Implement GET, POST, PUT and DELETE methods.
- Retrieve books using search and query parameters.
- Implement sorting and pagination.
- Filter books based on minimum and maximum prices.
- Validate user input before inserting or updating records.
- Return appropriate HTTP status codes.
- Handle errors using consistent JSON responses.
- Test API functionality using Postman.

## 7. Database Details

The project uses SQLite to store book information.

**Table Name:** `book`

| Column | Data Type | Description |
|---|---|---|
| id | INTEGER | Unique book ID |
| title | TEXT | Book title |
| author | TEXT | Book author |
| price | REAL | Book price |
| pages | INTEGER | Number of pages |

SQL queries use parameterized statements to reduce SQL injection risks.

## 8. API Endpoints

The following endpoints are implemented.

| HTTP Method | Endpoint | Description |
|---|---|---|
| GET | `/books/` | Retrieve all books |
| GET | `/books/:bookId/` | Retrieve a book by ID |
| POST | `/books/` | Add a new book |
| PUT | `/books/:bookId/` | Update an existing book |
| DELETE | `/books/:bookId/` | Delete a book |

## 9. Query Parameters

The GET `/books/` endpoint supports the following query parameters.

| Parameter | Description | Default Value |
|---|---|---|
| search_q | Search books by partial title | Empty string |
| order_by | Column used for sorting | id |
| order | Sorting direction (ASC or DESC) | ASC |
| limit | Maximum number of records | 10 |
| offset | Number of records to skip | 0 |
| min_price | Minimum book price | Optional |
| max_price | Maximum book price | Optional |

### Example Requests

**Search books:**

```text
GET /books/?search_q=Atomic
```

**Sort by price in descending order:**

```text
GET /books/?order_by=price&order=DESC
```

**Pagination:**

```text
GET /books/?limit=5&offset=0
```

**Price range filtering:**

```text
GET /books/?min_price=200&max_price=400
```

## 10. Input Validation

The POST and PUT endpoints validate the received request body.

The API checks:

- Title must be a non-empty string.
- Author must be a non-empty string.
- Price must be a valid non-negative number.
- Pages must be a positive integer.

If invalid data is submitted, the API returns HTTP 400 with a JSON error message.

Example validation response:

```json
{
  "message": "Provide valid title, author, numeric price and positive pages"
}
```

## 11. HTTP Status Codes

| Status Code | Meaning | Usage |
|---|---|---|
| 200 | OK | Successful GET, PUT and DELETE operations |
| 201 | Created | Book successfully added |
| 400 | Bad Request | Invalid input or query parameters |
| 404 | Not Found | Requested book does not exist |
| 500 | Internal Server Error | Unexpected server-side error |

Error responses follow a consistent JSON structure.

Example:

```json
{
  "message": "Book not found"
}
```

## 12. Debugging and Error Handling

The lab also covers common backend development errors and their solutions.

| Error | Explanation | Solution |
|---|---|---|
| EADDRINUSE | The requested port is already in use | Stop the existing process or use another port |
| Wrong import path | Incorrect module or file path | Verify the import path |
| Table name error | Incorrect database table name | Check the actual table name |
| Missing await | Asynchronous database operation is not awaited | Use `await` for database operations |

The API uses try-catch blocks to handle unexpected errors and return JSON error responses.
